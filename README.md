# Rana · OpenClaw — 跑在自己电脑上的多智能体 AI 伙伴

这是一个**个人项目**：以开源 AI 助手框架 **OpenClaw**（npm 包名 `openclaw`）为底座，在一台 Windows 主机上跑起三个性格分工不同的 AI 智能体（agent），再用一套完全自研的 Web 前端 **rana-web** 把它们装进一个有温度的界面里。她的原型是 MyGO!!!!! 里的**要乐奈**——所以整个界面是乐奈绿（`#77dd77`）配用户粉气泡，背景是一间纯 CSS/SVG 手绘的「她的房间」。

一句话说清楚它在干嘛：

> 微信上陪你聊的是**显卡上的本地她**（聊天内容不出本机）；QQ 私聊里干活的是**云端的她**（还能把编码重活派给 WSL 里的 DeepSeek 工人）；QQ 群里营业的是**物理隔离的公共号她**（只有群聊公开记忆）。三个她共用一套定时任务、每日早报、学习计划、跨会话长期记忆，以及一条互通近况但绝不泄露隐私的「三腿记忆桥」。

**开箱默认是单 Rana 形态**：陌生人 clone 后跑 `setup.cmd` → 双击启动 → 网页里填一个云端模型的 API key，就能和一个 Rana 聊天，全程不需要本地显卡。上面这套三智能体架构是作者自用配置，属于进阶玩法（见「快速上手」末尾的说明）。

## 🐣 新手村：这件事到底是怎么回事

把这台电脑想象成一家小店：

- **网关（gateway）** 是店里的总调度台。所有消息——不管来自微信、QQ 还是网页——都先到它这里，它决定叫哪个店员来接。
- **三个 agent（智能体）** 是三个店员：
  - `main` 是**干活的**：大脑在云端的 API（按用量付费），能执行电脑上的命令、查资料、跑统计，编码重活还能派给 DSH（WSL 里的 DeepSeek 编码工人）。你 QQ 私聊聊的就是她。
  - `rana-rp` 是**陪你聊天的**：大脑在你自己显卡上跑的本地微调模型，**聊天内容一个字都不会发到云端**。你微信上聊的就是她。
  - `rana-qq-public` 是**群里营业的**：云端大脑，只有群聊公开记忆，物理隔离——她拿不到你任何私人档案。
- **会话（session）** 就是一段一段的聊天记录，存在网关的 SQLite 数据库里。所以你在网页上发消息、在微信或 QQ 上发消息，记录都汇到同一个地方，网页上能同时看到。
- **cron（定时任务）** 是闹钟。到点让网关自动干活：每小时整理一次记忆、每天统计你写了多少代码，等等。
- **记忆（memory）** 是她记事的本子。每个 agent 有自己的长期记忆；几个 agent 之间还有「记忆桥」定时互通近况（详见[记忆体系](#-深入三个智能体与记忆体系)）。
- **rana-web（本仓库的主角）** 是你每天看到的那个网页：左边会话列表、中间聊天气泡、右边用量面板，顶部还有「Rana 的状态 / 定时任务 / 审批 / 早报 / 规划 / 程序 / 群画像 / 派活」页签（可以按住左右拖动换位置，顺序记在本地）。

**名词小抄**（后面章节会反复出现）：

| 词 | 人话解释 |
| --- | --- |
| provider | 模型供应商的接入配置（地址 + 密钥 + 模型列表）。云端如 dashscope，本地如 `lmstudio-local` |
| LM Studio | 一块本地跑大模型的软件， OpenAI 兼容接口，监听 `127.0.0.1:1234` |
| compaction（压缩） | 聊天太长时，网关自动把旧内容摘要压缩，腾出上下文空间 |
| contextWindow（上下文窗口） | 模型一次能「看进去」的字数上限，本地模型这块寸土寸金 |
| JIT 加载 | LM Studio 平时不占显存，请求来了才把模型拉进显存——但也因此容易出幺蛾子（见「模型运维」一节） |
| token | 模型计费和计量的最小单位，约等于半个到一个汉字 |

## 🚀 快速上手

### 开箱三步（新用户）

前置条件只有三样：**Windows** + **[Node.js 22+](https://nodejs.org)**（LTS 版即可）+ **任一 OpenAI 兼容云端模型的 API key**（智谱、阿里百炼/阿里云 MaaS、DeepSeek、OpenAI、硅基流动……都行）。不需要本地显卡。

1. **初始化**：双击仓库根目录的 `setup.cmd`。它会依次：检查 Node 版本 → 全局安装 OpenClaw（约 1-2 分钟）→ 在仓库内 `.openclaw\.openclaw\` 生成配置和 Rana 人格文件（含随机网关令牌）→ 安装前端依赖。**可重复执行**，已初始化的部分自动跳过。
2. **启动**：双击 `rana-web\start-rana.cmd`。网关（18789）+ 前端（5173）一起拉起，页面就绪后自动打开浏览器；已在跑的服务自动跳过，放心重复执行。**首次启动如果页面连不上，再双击一次 start-rana 即可**——OpenClaw 第一次启动会自动安装内置插件（anthropic/browser 等），装完要求重启一次才宣告就绪（网关窗口里会写明原因），第二次启动就正常了。
3. **填 key**：页面左侧「☁ 云端模型」→ 填服务商地址（baseUrl，http(s):// 开头）、API key → 「拉取模型列表」勾选 → 保存。**首个配置好的 provider 会自动成为默认模型**——回到聊天页，跟 Rana 说句话试试。

想改她的性格：编辑 `.openclaw\.openclaw\workspace-main\SOUL.md`（`setup-templates/` 里有出厂模板），改完新会话生效。想让 Rana 了解你：编辑同目录的 `USER.md`。

### 状态目录在哪、怎么挪

运行时状态（配置、会话记录、长期记忆、人格文件）全在仓库内 `.openclaw\.openclaw\`——已被 `.gitignore` 封禁，**永远不会被提交或发布**。想挪到别处：设环境变量 `OPENCLAW_STATE_DIR` 指过去；本机个性化（node 装在特殊位置等）用 `rana-web\local-overrides.cmd`（模板见 `local-overrides.example.cmd`，同样不入库）。

### 一键启动（本机日常用法）

双击 `rana-web\start-rana.cmd`，它会依次：

1. 发现 `18789` 没人监听 → 后台拉起 `start-gateway.cmd`（状态目录默认指向仓库内 `.openclaw\.openclaw`，`OPENCLAW_STATE_DIR` 环境变量优先；含 TLS 兼容参数；配置里存在本地 LM Studio provider 时顺带拉起 embedding 看门狗）；
2. 发现 `5173` 没人监听 → 后台 `npm run dev` 起 Vite；
3. 轮询等页面就绪（最长 60 秒）→ 自动打开默认浏览器。

启动脚本全部相对自身路径解析（node 走 PATH、openclaw.mjs 从 npm 全局目录自动探测），**换机器、换盘符、改目录名都不用改脚本**。

### 分步启动（想看清楚每一步）

```bash
# 1) 初始化（装 openclaw + 生成配置与人格 + 装前端依赖）
setup.cmd

# 2) 起网关（状态目录默认=仓库内 .openclaw\.openclaw，不用手动设变量）
cd rana-web && start-gateway.cmd

# 3) 另开一个终端起前端
cd rana-web && npm run dev

# 4) 打开 http://localhost:5173
```

**关于 token**：前端连网关需要鉴权 token。开发模式下前端会自动从 `/__rana/config` 端点读取状态目录里的 `openclaw.json` 拿到 token；如果拿不到（比如生产构建），在网页设置里手动粘贴即可。

**生产构建**：`npm run build` 产出静态文件，`npm run preview` 起预览服务（中间件在 preview 模式同样挂载，token 端点除外——这是刻意设计，见「中间件」一节）。

### 单 Rana 与「三个她」（进阶说明）

开箱形态是**单 agent 单人格**：一个 `main`（网页控制台直接聊）+ 一套 Rana 人格。本项目 README 后半部分描述的三智能体形态（本地 RP 她守微信、云端她守 QQ 私聊、公共号她守 QQ 群）是**作者自用配置**——OpenClaw 本身支持任意多 agent（`openclaw.json` 的 `agents.entries` 里加就是），本前端也做了跟随：界面上「多智能体才有的入口」（如侧栏的 RP 按钮）按配置里实际存在的 agent 自动显隐。想接微信/QQ 渠道、本地 LM Studio 模型，见下节与「本地模型运维」一章。

### 渠道与绑定（微信 / QQ）——进阶

三个 agent 各守一条渠道，绑定关系记录在状态目录的 `openclaw.json`（`bindings` 字段），**改绑定要重启网关**。开箱不包含渠道：微信走 `openclaw-weixin` 插件（需自己申请 bot 账号），QQ 走 `openclaw-qqbot` 插件（需在 QQ 开放平台建机器人拿 appId/clientSecret），配好插件与 bindings 后按需增配 agent：

| 渠道 | 值守的 agent | 说明 |
| --- | --- | --- |
| 微信 | `rana-rp` | 本地模型陪聊，对话不出本机 |
| QQ 私聊 | `main` | 云端干活主力，全套记忆与工具 |
| QQ 群 | `rana-qq-public` | 公共号，只有公开版记忆，物理隔离 |

> 历史注脚：早期做过「微信在 main / rana-rp 之间热切换」的批处理（`wechat-mode-*.cmd`），09-12 起已作废——三渠道三 agent 固定分工后不需要切了，本地残留文件仅作纪念。

## 🔌 深入：前端是怎么和网关对话的（协议 v4）

`src/lib/gateway.ts` 是整个前端的地基，约 760 行，值得单独讲。

### 握手：浏览器里的设备身份

大多数 Web 应用识别设备靠 cookie。本项目没有后端可种 cookie，于是把身份做进了浏览器：

1. 首次访问时，用 **WebCrypto 生成一对 Ed25519 密钥**，私钥存 localStorage，公钥的 SHA-256 哈希就是 `deviceId`；
2. 连上 WebSocket 后，网关先发 `connect.challenge`（时间戳 + 随机数）；
3. 浏览器用私钥对「设备信息 + token + 挑战值」的规范化串签名，连同公钥一起发回 `connect`；
4. 网关验签通过 → 回 `hello-ok`，连接正式建立。

好处：token 泄露不够冒充你（还得有私钥），换浏览器=新设备，无需任何服务端会话存储。

### 请求与事件：一个小型 RPC

- **请求**：`{type:"req", id, method, params}`，按 id 配对响应，每个请求带超时（普通 30s，删除链路 120s）；
- **事件**：`chat`（流式输出 delta/final/aborted/error/status 五态）、`sessions.changed`（会话变动，触发 1.5s 防抖刷新）、`session.message`（落库消息推送）、`cron`（任务变动）、`shutdown`。

流式渲染的核心状态在 `runs[sessionKey]`：一条消息从「乐观占位气泡」开始，delta 不断 patch 文本，final 落定，aborted/error 各有归宿。

### 为「不可靠的世界」做的防御（老手重点看这里）

网关是本机进程，但**慢**（SQLite 删除单个会话实测 ~7s）和**抖**（渠道长连接假死、浏览器休眠断线）是常态，所以连接层有一整套防御工事：

| 防御 | 解决什么 |
| --- | --- |
| 直连 4s 超时 → 自动改走同源 `/gateway` 代理 | 浏览器 Origin 被网关拒连时无感切换 |
| 指数退避重连（1s×2ⁿ 封顶 15s，最多 6 次） | 网关重启期间别疯狂敲门 |
| **乐观创建**：先给本地占位会话（`pending-create:` 前缀），后台等真实 key 再迁移消息与运行态；期间发消息自动等待创建完成 | 服务端建会话含 SQLite 写入较慢，界面不能等它 |
| **乐观删除**：界面立即移除，删除请求进**客户端串行队列**（并发会在超时处堆积误报）；超时后先查服务端确认真没删掉才重试；删除后 15 秒内继续过滤陈旧列表，防止会话「闪回」 | 慢删除 + 列表刷新竞态 |
| 归档用 `sessionId` 作乐观锁 | 删除瞬间别人也在改这条会话 |
| 三重去重：终态 runId 缓存 + 落库事件扫最近 8 条比对 + 删除中 key 集合 | 同一条消息可能从「流式渲染」「落库推送」「历史加载」三条路到达；compaction 会让 user 事件比 assistant 回复**晚到**，只比对最后一条会漏 |

## 🧩 深入：没有后端的全栈——Vite 中间件当后端

「网页要读电脑状态、要改配置文件，后端呢？」——**没有独立后端进程**。`vite.config.ts`（约 4,600 行）里写了十八组 Vite 插件，直接把接口挂到开发服务器上；`configurePreviewServer` 把同样的中间件挂到生产预览服务上，所以 `npm run dev` 和 `npm run preview` 行为一致，始终是单进程。

> 给新手的一句话：Vite 的开发服务器本质是个 Node 程序，允许你往它身上挂自己的接口。请求不进打包产物，只在本地服务器这一层就被拦下处理了。这对「纯本地自用」的工具来说是零成本的架构简化。

## ⚙️ 深入：边车脚本（自动化们）

定时自动化的形态刻意保持简单：**独立 Node 脚本 + cron 触发 + 文件契约**。脚本不依赖网关进程内的任何东西，输出落成本地 JSON 文件，前端只读文件——谁也不卡谁的脖子。

### memory-bridge.mjs — 三腿共享记忆桥（每小时）

三个 agent 各过各的日子，但她们应该知道该知道的事。这个脚本每小时跑一趟，三条腿：

1. **腿 1/2（双向）**：main 与 rana-rp 的新增对话分别提炼成简短纪要，写入共享目录（经 NTFS junction 同时挂在两边 workspace 的记忆区，双边记忆索引都能检索到），并同步一份「共享近况」到两边 `MEMORY.md` 的标记区块（这个文件每回合整体注入，保证必见）；
2. **腿 3（单向，群聊 → main）**：QQ 公共号的群聊新对话提炼成「群聊见闻」，**只写进 main 的记忆**——群里聊了什么她知道，main 的任何私货永远不会流向群聊侧；
3. **隐私规则不变**：提炼在哪边，原文就在哪边——RP 侧原文只发本地 LM Studio，工作侧/群聊侧原文本来就在云端；隐私词表（gitignore 的本地过滤表）做提示词层之下的兜底。

**化名机制**：群聊纪要一律写化名不写真名，真名/化名的映射关系外置在 gitignore 的 `memory-bridge.identity.json` 里（缺文件时回退中性称呼，桥照常跑）——连「某真名是某化名」这层映射本身都不进公开仓库、不进云端提示词。

另有一个**私密记忆桥**（`private-memory-bridge.mjs`，全链路本地、含行为账本「模型识别、代码计数」的设计），因属私人基础设施未入公开仓库，此处不展开。

### news-report.mjs — 早报生成器

抓 CCTV 新闻联播文字版（昨天那期，正则解析条目列表，直连不花额度）→ 博查 web-search 四个类目各搜一次（key 从配置读取，不硬编码）→ 云端 flash 模型写一段总结 → 落盘 `.news/report.json`。单板块失败跳过不拖垮整体；**总结失败不再静默**——report.json 里写 `summaryError` 字段，前端如实提示。

### study-agent.mjs / fate-agent.mjs — 专用会话桥（页面按需触发）

学习页的「让 Rana 排课/出题」和程序页的「解卦」不走普通聊天，而是把组装好的指令送进她的**专用会话**（`agent:main:study-planner` / `agent:main:fate-teller`），等她干完活把结果解析成 JSON 返回页面：180 秒超时 + 进程互斥（她一次只干一件事，排队不并发）。两个脚本共享 `lib/rana-config.mjs`（状态目录定位 + SecretRef apiKey 解析）。

### tools/embedding-watchdog.mjs — embedding 看门狗（随网关常驻）

把「模型运维」里最易复发的坑变成**死规则自动执行**：LM Studio 里 qwen3-embedding 必须**恰好一份实例、ctx 2048、纯 CPU**。看门狗由 `start-gateway.cmd` 顺带拉起（端口锁防多开），巡检发现实例数不对或参数漂移（比如记忆子系统 JIT 裂出的 ctx 8192 第二份）就自动 unload 全部 + 按标准参数重载。运维从「记得手动检查」变成「代码替你检查」。

> ctx 为什么从 32768 一路降到 2048：新后端（llama.cpp 2.40.0 CUDA）加载嵌入模型时强制 batch=ctx，缓冲区随 ctx 线性膨胀且拦不住地上 GPU——ctx 32768 要 10.7GB 显存、2048 只要 2.3GB。embedding 检索根本用不着长上下文，省下来的显存留给 14B 主模型。

### health-patrol.mjs — 零成本系统巡检（每 30 分钟）

心跳改造的产物：把「问她系统好不好」变成「脚本自己量」。一次跑完四项检查、**零模型调用**——网关端口在不在听、前端在不在听、QQ 通道是否 running/connected、私有备份仓最后一次提交是否超过 26 小时。结果写 `.health/patrol.json`（状态页巡检卡读它，历史留 2 天）；白天（08:00–23:00）某异常 3 小时内没报过才经 QQ Bot 主动发一条**聚合消息**给主人，深夜只记不发——异常要吼，但不能连环吼。退出码恒为 0，异常状态记在文件里，不污染 cron 收据。

### git-activity.mjs — Git 活动统计（日报/周报/月报）

回答「我今天/本周/本月干了什么」。两个有意思的口径设计：

- **只统计已推送的提交**（读本地 origin/main 引用，无需联网），避免「本地写了又删」的噪音；
- **自动提交单独归栏**：本仓库日常被两个脚本全量自动提交（`sync:` / `backup` 前缀），直接统计会被机器灌水淹没——按前缀正则拆成「实质工作 / 自动同步」两栏，代表性提交只从实质工作里挑。

触发方式上有个绕坑的故事：OpenClaw cron 官方的触发脚本 DSL 被安全扫描钩子一刀切拦截（静态规则无法区分有无用户输入拼接），最终改用「系统事件」方案——cron 到点向 main 会话发一条系统事件，让 main 的 Rana **自己跑统计脚本并用人话汇报**（详见 KNOWN-ISSUES 登记）。

## 🧩 Skill 清单与系统运行方式（给人看，也给 code agent 看）

> 本章是「能力清单 + 运行班表 + 排障路线」三合一。人看懂她都会什么；code agent 进场先读这章再动手——定位问题先对班表，再按排障路线走。

### Skill 是什么、装在哪、怎么查

OpenClaw 的 **skill（技能）** 是给 agent 的专项能力包：一个目录 + 一份 `SKILL.md`（写名称、用途、**触发词**），agent 在对话里听到匹配的语义就自动取用，不需要人点按钮。三个层次：

- **自装技能**：状态目录 `workspace-<agent>/skills/` 下（gitignore，不入公开仓库）；本节清单即全部自装技能；
- **内置技能**：随 OpenClaw npm 包分发（github、healthcheck 等通用件），按配置对 agent 可见；
- **系统任务型**：`skill-collection-review`（每 7 天技能回顾）、心跳、记忆做梦——属 memory-core 系统任务，定时任务页标「⚙ 系统」，不可单独启停。

实时清单两处可查：网页右侧「🛠 技能 / 🔌 MCP」卡（走 `/__rana/agent-info`），或命令行 `openclaw skills list --agent <id>`（需带 `OPENCLAW_STATE_DIR`）。

### 进程拓扑：谁常驻、谁即起即灭

- **常驻三件**：网关（含全部 cron、渠道连接、记忆索引）、Vite dev/preview（十八组中间件即后端）、embedding 看门狗（由 `start-gateway.cmd` 顺带拉起，端口锁防多开）；
- **即起即灭**：边车脚本（cron 到点拉起，跑完退出）、专用会话桥（页面动作拉起）、`agent-info` 的 CLI 子进程；
- **改动的生效方式**：`openclaw.json` 保存即热重载；`bindings` 渠道绑定要重启网关；前端代码 Vite 热更；`SOUL/AGENTS/MEMORY` 等人格记忆文件开新会话生效。

### code agent 排障路线（10 分钟法则）

1. **先查 [KNOWN-ISSUES.md](KNOWN-ISSUES.md)**——按症状关键词搜，命中直接照方抓药；
2. **日志**：`%TEMP%\openclaw\openclaw-当日.log`（JSON-lines）。高频关键词速查：
   - `stalled session` → 有会话卡住，看 `activeTool=` 是谁卡的；若配 `approval-handler` / `waitDecision` 即**审批卡死**（隔离会话审批送不到人，只能 `openclaw approvals resolve <id> allow-once` 解救或重启网关）；
   - `cron: job execution timed out` → 任务撞执行上限（turn 可能仍在后台跑完，**以 transcript 为准**而非收据）；
   - `cron: job run returned error status` / `scheduling recurring retry after transient error` → 任务失败与重试，紧跟的 `outcome=error duration=` 行有详情；
   - `timer tick failed` → cron 调度层问题（典型：任务解析不出 owner）；
   - `weixin getUpdates error` → 微信长连接抖动，连续出现才处理（重启网关即愈）；
3. **`openclaw cron list`** 对班表看全班状态（`error (Nx)` = 连败 N 次），`openclaw cron run <id>` 手动补跑验证；
4. **状态页巡检卡 / `.health/patrol.json`** 看端口/通道/备份新鲜度；
5. **纪律**：排障超 10 分钟必须回写 KNOWN-ISSUES（AGENTS.md 铁律）；隔离会话（cron/isolated）禁 exec——审批卡送不出去就是 900 秒死循环；exec 审批白名单只放 git.exe，**解释器（node/python）永不放行**（路径级放行=闸门失效）；改配置前先备份；密钥只在密钥库与 gitignore 文件里。

多 agent 模式下网关要求请求显式指定 owner（`agentId`），这是前端部分请求要带 `agentId` 的原因。

### 记忆的分层结构

```
┌─ 各自 workspace 的记忆（MEMORY.md 即时注入 + 长期记忆库语义检索）
│    main:    底稿 + 索引式 MEMORY + 工程台账 + 项目档案 + heart-context（最高机密）
│    RP:      SOUL.private（仅本地模型注入，云端永远读不到）+ 私密记忆桥
│    公共号:  只有公开版记忆
│
├─ 三腿共享记忆桥（每小时一班）
│    main ⇄ rana-rp      双向：互相知道对方近况
│    群聊 → main         单向：群里聊了什么她记着，私货绝不过去
│    └─ 隐私规则：提炼在哪边、原文就在哪边；群纪要一律化名（映射外置 gitignore）
│
└─ 私密记忆（独立目录：不在任何 workspace、不被记忆索引扫描、不被共享桥读取）
```

设计原则一句话：**数据往哪个层级流，取决于它最私密的时候在哪**。私密对话先在本地被提炼成「能见人」的纪要，才允许过桥；提炼这个过程本身也不经过任何云端。

### 公开镜像的隐私纪律

本仓库通过 `push-public.cmd`（`git add -A` 全量）镜像到公开仓库，所以**任何入库文件默认视为公开**：

- 密钥/token/个人账号 ID/私有仓库地址，绝对禁入；
- 状态目录（`.openclaw/`）、会话数据、SOUL/USER/MEMORY 等人格与记忆文件、日志、probe 调试脚本、隐私词表、私密记忆桥、Git 仓库清单（暴露本地目录结构）——全部在 `.gitignore` 里点名封禁；
- `push-public.cmd` 与 `backup-private.cmd` 本身也因含私有仓库地址而不入库。

## 🎮 深入：本地模型运维（12GB 显存生存指南）

在 4070 Ti 12GB 上让「一个 14B 模型常驻 + 随叫随到」稳定运行，是本项目踩坑最密集的区域，台账里有三篇大案。这里把结论沉淀成运维守则：

1. **LM Studio 的 JIT 按「模型 + 配置」区分实例**：同一个模型，两次以不同 `context_length` 加载 = 两份权重同时驻留显存。表现为模型名带 `:2` 后缀。解法：全卸载后，用与调用方**完全一致的参数**显式加载一份常驻（显式 load 无 TTL）。同参复打只会复用，不会再裂。
2. **查真实驻留要用 `/api/v0/models`**：`/v1/models` 会把没加载的也列出来，会骗人。
3. **parallel 槽会平分上下文**：`context_length=49152, parallel=2` = 每槽只有 24576。单请求预算（约 12.7k）+ 最大输出（8k）必须小于单槽，否则顶破。
4. **KV 缓存可以卸到系统内存**：48GB 内存充裕时，`offload_kv_cache_to_gpu=false` 让 GPU 只留权重，显存立刻宽松。
5. **压缩预算的硬地板**：OpenClaw 的上下文压缩预算公式里有一个 20000 token 的保留区下限——`contextWindow` 提到 24576 时预算仍是 8000，必须 ≥32768 预算才真正变大。预算太小会导致每 1~2 条消息就压缩一次，每压缩一次要动用两个模型（摘要 + 记忆冲刷），显存直接连环爆。
6. **memoryFlush 模型要跟着主模型走**：压缩时的记忆冲刷如果还指向换掉前的旧模型，那个旧模型会被反复拉进显存陪跑。脚本侧同理——记忆桥的提炼模型从 agent 配置动态读取，不写死。
7. **最易复发的规则交给看门狗**：embedding 模型的「恰好一份、纯 CPU、ctx 2048」由 `tools/embedding-watchdog.mjs` 随网关常驻巡检，发现 JIT 裂出的第二份（ctx 8192 特征）或参数漂移就自动卸载重载——守则 1 靠人记，守则 7 靠代码记。

## 🌟 技术亮点分析

以上是「怎么做的」，这一节回答「哪些做法值得你偷走」。

### 1. 「没有后端的全栈」：Vite 插件即后端
对一个纯本机自用工具，独立后端进程是纯负债：要管生命周期、要定接口协议、要处理跨进程配置。本项目把后端做成 Vite 插件挂进 dev/preview 两个服务器，**单进程、零部署、与前端同生命周期**；将来若真要上公网，这一摞中间件可以原样搬进任何 Node HTTP 服务器，因为它们本来就只依赖 Node 标准 API，没有一行 Vite 私有代码。

### 2. 浏览器里的设备身份
不靠 cookie、不靠服务端会话表，用 WebCrypto Ed25519 完成「挑战-签名-验证」三步握手。这个模式值得一切「无后端/弱后端」的本地工具参考：**凭据（token）与身份（私钥）分离**，泄露前者不等于冒充。

### 3. 为不可靠世界设计的连接层
「网关协议」那节防御工事表格的本质是一个认知：**本地进程≠可靠，SQLite 写入、渠道长连接、浏览器休眠都会制造竞态**。乐观创建的占位 key 协议（`pending-create:` 前缀 + Promise 队列 + 完成迁移）、删除的串行链 + 「超时先核实再重试」、消息三路到达的去重——每一招都对应一个真实踩过的坑（台账可查），不是教科书式防御。

### 4. 脏输出清洗管线
微调小模型的输出是「脏」的：伪思维链塞在 `<details>` 里、运行时注入的指令封套被原样吐回、甚至模仿着写出 `## Chat history` 的档案结构。`reasoning.ts` 用一条管线把这些全部洗干净：多源思考折叠（`<think>` / `<details>` 双语法、流式未闭合也要处理）→ 封套剥离 → 元块清除 → 回声检测（整条只剩封套时折叠成占位行）。**在 UI 层兜住模型层的问题**，是跟本地小模型共处的必修课。

### 5. 隐私是一等公民的架构，不是开关
隐私不是「加个加密」这种事后补丁，而是数据流本身的形状：私密对话的提炼发生在本地、过桥的只有纪要、私密记忆放在**结构上不可被索引**的目录、人格文件用 fail-closed 的钩子注入、公开镜像用 gitignore 点名封禁 + 全量提交前人工过闸。每一层的默认状态都是「不出去」。

### 6. 界面优先 + 文件契约的自动化
教训驱动的两条铁律：**自动化不许往聊天会话里塞消息**（早报曾占用车道，后来改成独立页面按需生成）；**功能必须长在界面上**（cron 系统任务关不掉？UI 如实标注而不是假装能关）。边车脚本与前端之间只用文件（`report.json`）对话，互相不依赖进程存活。按需生成 + 进程互斥锁把 API 额度从「每天固定烧」变成「用了才烧」。

### 7. 把踩坑制度化：人和 agent 共读的台账
`KNOWN-ISSUES.md` 不只是笔记，它是**写给下一个 code agent 的程序**：统一的「症状/根因/解决方案/状态」模板，AGENTS.md 规定排障先查它、解决后必须回写。同一个坑第二次出现时（如 LM Studio 双实例第二次发作），直接模式匹配到旧条目，几分钟收敛。配套的两层 AGENTS.md 体系（全局红线 + 项目规范）让任何一家 code agent 进场都自带同一套纪律。

### 8. 中文 Windows 环境的生存补丁集
GBK 输出解码、PowerShell 显式 UTF8、Node `--tls-max-v1.2` 绕 TLS 1.3 后量子 ClientHello 兼容问题、Hyper-V/winnat 动态端口保留段圈占代理端口（`net stop winnat` 大法）——这些平台怪癖每一个都能耗掉一晚上，本项目全部踩过、全部登记、全部有照方抓药的命令。

### 9. 定量化的模型运维
显存问题不靠玄学靠算术：压缩预算公式推导、parallel 槽平分上下文的验算、JIT 双实例的机理归因、KV 卸载的取舍——「模型运维」每条守则背后都有一次完整的测量与复验记录；最易复发的 embedding 规则更是直接固化成了看门狗代码。这套方法比任何「调参秘籍」都可靠。

### 10. 角色浓度是工程出来的
「她的房间」不是贴图：墙、窗、搁板上的抹茶芭菲/毛线球/铃铛、角落的 ESP POTBELLY 吉他剪影，全是 CSS/SVG 手绘（不引版权图）；主题系统用 `color-mix` 从一个 accent 变量派生整套配色，用户粉气泡固定不随主题漂移；所有动画尊重系统「减少动态效果」设置。角色一致性靠设计系统，不靠贴皮。

## 🧯 排障与已知问题

**排障第一步永远是查 [KNOWN-ISSUES.md](KNOWN-ISSUES.md)**——先搜症状关键词，命中直接照方抓药。台账当前已登记的典型案件：

- 微信会话被 `ask_user` 卡死 15 分钟（已禁用该工具）+ 微信长连接假死（重启网关即愈）；
- 微信通道整条静默死亡——网关进程丢了 `OPENCLAW_STATE_DIR`，微信插件回落主目录找不到账号（已用用户级 `setx` 根治，`channelAccounts` 空数组是诊断抓手）；
- 微信主动推送依赖 contextToken（上游限制：用户先发一条消息即恢复）；
- LM Studio 同模型双实例挤爆显存（模型运维守则 1，embedding 侧已有看门狗兜底）；
- 隔离类 cron（心跳/画像）被 qwen3.8-flash 一律 400 拒绝（已缓解，根因待查）；
- "Automation" run 会话删不掉——gateway 不认 run 会话 + placement 残留卡死父会话（按台账手术法清理）；
- Clash 代理端口 7897 被 Hyper-V 动态端口保留段圈占 → git 推送挂死（`net stop winnat` 重算）；
- 大文件卷进 git → 推送永久挂死 → 心跳连环超时（reflog + gc 手术）；
- cron 会话删除报 `did not finish stopping`（placement 残留，需按 session_key 手术）；
- Windows 网关下 cron 命令要用 `--command-argv` JSON 数组（没有 sh 可用）。

**日常运维**：

- 重启网关：任务管理器结束 node 进程（或 `taskkill`）→ 重跑 `rana-web/start-gateway.cmd`（无服务注册，进程死了就是死了；它会顺带拉起 embedding 看门狗，端口锁防多开）；
- 网关日志：启动窗口直接看，或经 `tmp-restart-gateway.cmd` 包装重定向到 `rana-web/tmp-gw-restart.log`；网关自身日志在 `%TEMP%\openclaw\openclaw-当日.log`（搜 `stalled session`、`timer tick failed`），看门狗日志在 `%TEMP%\openclaw\embedding-watchdog.log`；
- 前端排障：浏览器控制台（连接层日志都带 `[gateway]` 前缀）+ `window.gw` 调试钩子可直接在控制台调用网关接口；单页崩了有 ErrorBoundary 兜底，坏一块重载一块，不再整站白屏。

## ❓ FAQ（新手高频）

**Q：打开页面一直「未连接」？**
网关没起来。跑一遍 `start-rana.cmd`；还不行就看设置里 token 填了没（连接层报「缺少 gateway token」时会在横幅里明说）。

**Q：开箱版和作者的三智能体形态差在哪？**
功能同一个前端、同一套网关。差别只在 `openclaw.json`：开箱模板只有 `main` 一个 agent + 云端模型；作者配置多了本地 RP agent（微信）、QQ 群公共号、记忆桥等边车。多智能体入口（如侧栏 RP 按钮）按配置自动显隐，加 agent 不用改前端代码。

**Q：怎么改她的性格 / 让她认识我？**
编辑状态目录 `workspace-main\SOUL.md`（人格）和 `USER.md`（你的介绍），模板见仓库 `setup-templates/`。改完开新会话生效。

**Q：她在微信/QQ 里和网页上是同一个她吗？**
同一个网关、同一份会话存储，但**不同渠道由不同人格值守**：微信是本地陪聊的 RP，QQ 私聊是云端干活的 main，QQ 群是物理隔离的公共号。网页控制台是总览——三个她的会话都看得到、都能聊。

**Q：为什么她的回复里有一段灰色的「思考过程」？**
本地模型习惯把推理写在正文前。前端解析出来折叠了，点开可看，顶栏 💭 按钮可整体关闭。

**Q：某个定时任务想关但开关是灰的？**
那是 OpenClaw 内置的系统级任务，上游不开放单独启停（只能全局配置关）。UI 如实标了「⚙ 系统」。

**Q：显存又爆了/机器很卡？**
按「模型运维」守则逐条检查：`/api/v0/models` 看有没有 `:2` 实例、有没有旧模型陪跑、contextWindow 是否 ≥32768、看门狗是否在跑。

**Q：想自己改点什么，从哪下手？**
加页面：`src/components/` 建组件 → `App.tsx` 挂视图 → `src/lib/types.ts` 的 `NAV_TABS` 加页签（**单一来源**，页签顺序/合法性都由它派生，别在别处再抄一份清单——这是踩过坑的）。要本地数据就照现有中间件的样子在 `vite.config.ts` 加一组（记得回环校验）。改之前读一遍根目录 `AGENTS.md` 的规矩。

**Q：为什么叫 Rana？界面为什么长这样？**
原型是 MyGO!!!!! 的要乐奈：铃铛、异色瞳（导航栏那对双色圆点）、乐奈绿主色、墙上的吉他，都是给她的应援。设计稿的演进过程（五版）完整保留在 `rana-web/design-mockups/`。
