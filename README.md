# Rana · OpenClaw — 跑在自己电脑上的双智能体 AI 伙伴

这是一个**个人项目**：以开源 AI 助手框架 **OpenClaw**（npm 包名 `openclaw`）为底座，在一台 Windows 主机上跑起两个性格分工不同的 AI 智能体（agent），再用一套完全自研的 Web 前端 **rana-web** 把它们装进一个有温度的界面里。她的原型是 MyGO!!!!! 里的**要乐奈**——所以整个界面是乐奈绿（`#77dd77`）配用户粉气泡，背景是一间纯 CSS/SVG 手绘的「她的房间」。

一句话说清楚它在干嘛：

> 微信和网页都能跟她聊天；云端模型负责干活（main），本地显卡上的微调模型负责陪伴（rana-rp）；有定时任务、每日早报、学习课程表、跨会话的长期记忆，还有一条在两个智能体之间共享记忆、但绝不泄露隐私的「记忆桥」。

## 🐣 新手村：这件事到底是怎么回事

把这台电脑想象成一家小店：

- **网关（gateway）** 是店里的总调度台。所有消息——不管来自微信还是网页——都先到它这里，它决定叫哪个店员来接。
- **两个 agent（智能体）** 是两个店员：
  - `main` 是**干活的**：大脑在云端的 API（按用量付费），能执行电脑上的命令、查资料、跑统计。你微信上聊的就是她。
  - `rana-rp` 是**陪你聊天的**：大脑在你自己显卡上跑的本地微调模型，**聊天内容一个字都不会发到云端**。网页上有专门的「Rana·RP」会话入口。
- **会话（session）** 就是一段一段的聊天记录，存在网关的 SQLite 数据库里。所以你在网页上发消息、在微信上发消息，记录都汇到同一个地方，网页上能同时看到两边。
- **cron（定时任务）** 是闹钟。到点让网关自动干活：每半小时整理一次记忆、每天统计你写了多少代码，等等。
- **记忆（memory）** 是她记事的本子。每个 agent 有自己的长期记忆；两个 agent 之间还有一座「记忆桥」定时互通近况（详见[记忆体系](#-深入双智能体与记忆体系)）。
- **rana-web（本仓库的主角）** 是你每天看到的那个网页：左边会话列表、中间聊天气泡、右边用量面板，顶部还有「Rana 的状态 / 定时任务 / 早报 / 学习计划 / 程序」页签（可以按住左右拖动换位置，顺序记在本地）。

**名词小抄**（后面章节会反复出现）：

| 词 | 人话解释 |
| --- | --- |
| provider | 模型供应商的接入配置（地址 + 密钥 + 模型列表）。云端如 dashscope，本地如 `lmstudio-local` |
| LM Studio | 一块本地跑大模型的软件， OpenAI 兼容接口，监听 `127.0.0.1:1234` |
| compaction（压缩） | 聊天太长时，网关自动把旧内容摘要压缩，腾出上下文空间 |
| contextWindow（上下文窗口） | 模型一次能「看进去」的字数上限，本地模型这块寸土寸金 |
| JIT 加载 | LM Studio 平时不占显存，请求来了才把模型拉进显存——但也因此容易出幺蛾子（见 §12） |
| token | 模型计费和计量的最小单位，约等于半个到一个汉字 |

## 🚀 快速上手

### 先说清楚：克隆这个仓库你会得到什么

本仓库是**公开镜像**，包含前端、边车脚本和文档。但网关本体、智能体配置、会话记录、长期记忆都在本机的 OpenClaw 状态目录里（`openclaw.json`、SQLite 等），**不入 git**。所以：

- 只想看看代码 / 复用某部分设计 → 克隆即读，各模块自包含；
- 想完整跑一套 → 需要先自备：Node 18+、OpenClaw（`npm i -g openclaw` 后初始化生成状态目录）、以及可选的 LM Studio + 本地模型。

### 一键启动（本机日常用法）

双击 `start-rana.cmd`（或仓库根的 `Rana Web.lnk`），它会依次：

1. 发现 `18789` 没人监听 → 后台拉起 `start-gateway.cmd`（带 `OPENCLAW_STATE_DIR` 环境变量和 TLS 兼容参数）；
2. 发现 `5173` 没人监听 → 后台 `npm run dev` 起 Vite；
3. 轮询等页面就绪（最长 60 秒）→ 自动打开默认浏览器。

已经在跑的服务会自动跳过，可以放心重复执行。

### 分步启动（想看清楚每一步）

```bash
# 1) 装依赖
cd rana-web && npm install

# 2) 起网关（注意：必须带状态目录环境变量，否则读到的是另一个空目录）
set OPENCLAW_STATE_DIR=K:\openclaw\.openclaw\.openclaw
openclaw gateway

# 3) 另开一个终端起前端
cd rana-web && npm run dev

# 4) 打开 http://localhost:5173
```

**关于 token**：前端连网关需要鉴权 token。开发模式下前端会自动从 `/__rana/config` 端点读取状态目录里的 `openclaw.json` 拿到 token；如果拿不到（比如生产构建），在网页设置里手动粘贴即可。

**生产构建**：`npm run build` 产出静态文件，`npm run preview` 起预览服务（中间件在 preview 模式同样挂载，token 端点除外——这是刻意设计，见 §9）。

### 微信渠道

微信接入由网关的渠道模块负责（ilink 协议），配置好后她可以直接在微信里应答。两个批处理 `wechat-mode-*.cmd` 可以在不重启网关的情况下把微信绑定的 agent 在 main / rana-rp 之间热切换（此二脚本含个人路径，未入公开仓库）。

## 🖥️ 界面功能总览

四个页签 + 三层弹窗，全部功能都长在界面上，**命令行只做兜底**（这是本项目的铁律，详见 §13 亮点 6）。

### 💬 会话（主页）
- 流式输出气泡，带「准备工作区…启动模型…」的**状态行**（run 生命周期可视化）；
- **思考过程折叠**：模型输出的 `<think>` 块、微调模型写在 `<details><summary>` 里的伪思维链，都会被解析折叠成可展开的小块，顶栏一键开关；
- 会话管理：新建（可选 agent）、置顶、重命名、删除、未读角标——全部是**乐观更新**（点完立刻生效，慢操作转后台，详见 §8）；
- 微信等外部渠道的来话/回话实时出现在对应会话里（订阅推送），不在电脑前也能用微信续上同一段对话；
- 右侧**用量面板**：每个会话的 token 消耗与预估成本；
- 顶栏**模型选择器**按 provider 分组展示全部模型（含上下文窗口大小），点选即切换当前会话模型（热生效）。

### 🖥️ 电脑状态
硬盘/内存/CPU 负载/开机时长聚合展示（8 秒缓存）、**显卡**状态（nvidia-smi：型号/显存/温度/利用率）、**电源计划**一键切换（powercfg）。没有显卡或命令缺失时各自独立降级，不影响其他卡片。

### ⏰ 定时任务
列出网关全部 cron 任务，支持手动运行、启停。OpenClaw 内置的系统级任务（技能回顾/心跳）不允许被单独启停——UI 如实标注「⚙ 系统」并把开关禁用，而不是给你一个点了没反应的假按钮。

### 📰 早报
每天的第一份资讯：CCTV 新闻联播文字版条目（直抓官网，不花额度）+ 博查搜索四个类目（AI 前沿/科技动态/国内时事/国际视野）+ 右侧「乐奈的总结」小卡（云端 flash 模型一次总结）。**省额度设计：当天第一次打开这个页面才触发生成**，不开页面零查询。

### 📚 学习计划
真实日期的月历课程表（不是循环课），一套完整的学习闭环：
- **排课**：上传学习任务书、点「让Rana排课」，她按资料排进日历——自动估时、超 90 分钟拆成两节、每天最多 3 节不超 3 小时（超载的格子月历标红）、有依赖的课自动串前置；微信里发文件让她排也一样。
- **执行**：每节课标「学完 / 没完成（自动顺延到下一个空白天）」；学完自动排 +1/+7/+16 天三节复习课（间隔复习）；设了时段的课到点弹浏览器通知，显卡还在满负荷时她会提醒你"游戏先放放"；月历可切**周视图**（一列一天、当天全部课放开看）。

## 🔌 深入：前端是怎么和网关对话的（协议 v4）

`src/lib/gateway.ts` 是整个前端的地基，750 行，值得单独讲。

### 握手：浏览器里的设备身份

大多数 Web 应用识别设备靠 cookie。本项目没有后端可种 cookie，于是把身份做进了浏览器：

1. 首次访问时，用 **WebCrypto 生成一对 Ed25519 密钥**，私钥存 localStorage，公钥的 SHA-256 哈希就是 `deviceId`；
2. 连上 WebSocket 后，网关先发 `connect.challenge`（时间戳 + 随机数）；
3. 浏览器用私钥对「设备信息 + token + 挑战值」的规范化串签名，连同公钥一起发回 `connect`；
4. 网关验签通过 → 回 `hello-ok`，连接正式建立。

好处：token 泄露不够冒充你（还得有私钥），换浏览器=新设备，无需任何服务端会话存储。

### 请求与事件：一个小型 RPC

- **请求**：`{type:"req", id, method, params}`，按 id 配对响应，每个请求带超时（普通 30s，删除链路 120s）；
- **事件**：`chat`（流式输出 delta/final/aborted/error/status 五态）、`sessions.changed`（会话变动，触发 1.5s 防抖刷新）、`session.message`（落库消息推送）、`cron`（任务变动）、`shutdown`。

流式渲染的核心状态在 `runs[sessionKey]`：一条消息从「乐观占位气泡」开始，delta 不断 patch 文本，final 落定，aborted/error 各有归宿。

### 为「不可靠的世界」做的防御（老手重点看这里）

网关是本机进程，但**慢**（SQLite 删除单个会话实测 ~7s）和**抖**（微信长连接假死、浏览器休眠断线）是常态，所以连接层有一整套防御工事：

| 防御 | 解决什么 |
| --- | --- |
| 直连 4s 超时 → 自动改走同源 `/gateway` 代理 | 浏览器 Origin 被网关拒连时无感切换 |
| 指数退避重连（1s×2ⁿ 封顶 15s，最多 6 次） | 网关重启期间别疯狂敲门 |
| **乐观创建**：先给本地占位会话（`pending-create:` 前缀），后台等真实 key 再迁移消息与运行态；期间发消息自动等待创建完成 | 服务端建会话含 SQLite 写入较慢，界面不能等它 |
| **乐观删除**：界面立即移除，删除请求进**客户端串行队列**（并发会在超时处堆积误报）；超时后先查服务端确认真没删掉才重试；删除后 15 秒内继续过滤陈旧列表，防止会话「闪回」 | 慢删除 + 列表刷新竞态 |
| 归档用 `sessionId` 作乐观锁 | 删除瞬间别人也在改这条会话 |
| 三重去重：终态 runId 缓存 + 落库事件扫最近 8 条比对 + 删除中 key 集合 | 同一条消息可能从「流式渲染」「落库推送」「历史加载」三条路到达；compaction 会让 user 事件比 assistant 回复**晚到**，只比对最后一条会漏 |

## 🧩 深入：没有后端的全栈——Vite 中间件当后端

「网页要读电脑状态、要改配置文件，后端呢？」——**没有独立后端进程**。`vite.config.ts`（约 1000 行）里写了六组 Vite 插件，直接把接口挂到开发服务器上；`configurePreviewServer` 把同样的中间件挂到生产预览服务上，所以 `npm run dev` 和 `npm run preview` 行为一致，始终是单进程。

> 给新手的一句话：Vite 的开发服务器本质是个 Node 程序，允许你往它身上挂自己的接口。请求不进打包产物，只在本地服务器这一层就被拦下处理了。这对「纯本地自用」的工具来说是零成本的架构简化。

| 端点 | 干什么 | 关键设计 |
| --- | --- | --- |
| `GET /__rana/config` | 给前端发网关 token | **只挂 dev 模式**；生产构建必须手动填 token，防止静态部署时泄露 |
| `/__rana/provider-config` | 云端 provider 增改删（直接写 `openclaw.json`，网关文件监听自动热重载） | API key 列表里**打码**显示；删除前做**引用检查**（还有 agent 在用就拒删）；每次写前自动备份 `.bak-cloud`；保留既有模型条目的扩展字段不被 UI 覆盖 |
| `POST /__rana/provider-models` | 服务端代理拉取供应商的 `/models` 列表 | 规避浏览器 CORS，key 不经过前端明文流转 |
| `GET /__rana/sys/status` | 聚合硬盘/CPU/内存/开机时长/显卡(+显存进程明细)/电源计划/虚拟化/服务端口/网速/外网连通 | 8 秒缓存；子进程一律 `execFile` **数组参数**（不经 shell、无拼接注入面）；powercfg 输出是 GBK，按字节接收再 `TextDecoder("gbk")` 解码。服务端口 = 默认四件套（网关18789/前端5173/LM Studio 1234/Clash 7897）+ `rana-web/services.json` 自加项，附进程名与已运行时长；每进程显存用 GPU 性能计数器查（nvidia-smi 在 WDDM 下查不到，全是 [N/A]）；网速=物理网卡字节差分（排除 vEthernet 防重复计数）；外网连通（GitHub 走 Clash 代理 / 模型 API 直连）用 curl 探测，**60 秒缓存**别一直敲人家的门 |
| `POST /__rana/sys/power` | 切换电源计划 | **仅接受 GUID 格式参数**（正则白名单，天然无注入）+ 仅本机回环 |
| `/__rana/avatar` | 头像上传/读取/恢复默认 | png/jpg/webp ≤4MB，类型由 content-type 白名单判定；文件只存本地 gitignore 目录 |
| `/__rana/news` | 读早报数据 + 触发生成 | POST 触发 `news-report.mjs` 子进程（90s 超时）；**进程级互斥锁**防并发重复生成（React 开发模式 effect 会跑两次，这是真踩过的坑） |
| `/__rana/study/*` | 学习课程表读写 + 唤醒她排课/出题/判分 | 数据在本地 `.study/`（gitignore）；排课/出题走 `study-agent.mjs` 子进程连网关，往专用会话 `agent:main:study-planner` 发消息（180s 超时 + 互斥：她一次只干一件事）；判分成绩由中间件写回；资料删除前做**课程引用检查**；课程条目服务端清洗（日期/时段格式、id 唯一） |
| `/__rana/fate/*` | 问卜：生辰档案存取 + 解卦转发 | 档案在本地 `.fate/`（gitignore，写前 .bak）；万年历/八字/紫微全在浏览器本地算（lunar-javascript + iztro），中间件只管档案与把前端算好的命盘摘要组装成提示词 → `fate-agent.mjs` 子进程（专用会话，180s 超时+互斥）→ 她的解卦 markdown 直接返回页面 |

所有**写操作**端点都做双重来源校验：socket 必须是本机回环地址 + Origin 头必须匹配 localhost。这套东西不面向公网，但也没有裸奔。

## ⚙️ 深入：边车脚本（自动化们）

定时自动化的形态刻意保持简单：**独立 Node 脚本 + cron 触发 + 文件契约**。脚本不依赖网关进程内的任何东西，输出落成本地 JSON 文件，前端只读文件——谁也不卡谁的脖子。

### memory-bridge.mjs — 共享记忆桥（每 30 分钟）

两个 agent 各过各的日子，但她们应该知道对方最近干了什么。这个脚本每半小时：

1. 分别读两个 agent 的 SQLite 会话库，取出**上次桥接之后的新增对话**；
2. 各自提炼成简短纪要——**提炼在哪边，原文就在哪边**：RP 侧的原文只发给本地 LM Studio 模型；工作侧原文本来就在云端，发给云端模型；
3. 纪要写入共享目录（经 NTFS junction 同时挂在两个 workspace 的记忆区，双边记忆索引都能检索到），并同步一份「共享近况」到两边 `MEMORY.md` 的标记区块（这个文件每回合整体注入，保证必见）。

另有一个**私密记忆桥**（`private-memory-bridge.mjs`，全链路本地、含行为账本「模型识别、代码计数」的设计），因属私人基础设施未入公开仓库，此处不展开。

### news-report.mjs — 早报生成器

抓 CCTV 新闻联播文字版（昨天那期，正则解析条目列表，直连不花额度）→ 博查 web-search 四个类目各搜一次（key 从 `openclaw.json` 读取，不硬编码）→ 云端 flash 模型写一段总结 → 落盘 `.news/report.json`。单板块失败跳过不拖垮整体。

### git-activity.mjs — Git 活动统计（日报/周报/月报）

回答「我今天/本周/本月干了什么」。两个有意思的口径设计：

- **只统计已推送的提交**（读本地 origin/main 引用，无需联网），避免「本地写了又删」的噪音；
- **自动提交单独归栏**：本仓库日常被两个脚本全量自动提交（`sync:` / `backup` 前缀），直接统计会被机器灌水淹没——按前缀正则拆成「实质工作 / 自动同步」两栏，代表性提交只从实质工作里挑。

触发方式上有个绕坑的故事：OpenClaw cron 官方的触发脚本 DSL 被安全扫描钩子一刀切拦截（静态规则无法区分有无用户输入拼接），最终改用「系统事件」方案——cron 到点向 main 会话发一条系统事件，让 main 的 Rana **自己跑统计脚本并用人话汇报**（详见 KNOWN-ISSUES 登记）。

## 🧠 深入：双智能体与记忆体系

### 两个 agent，一张清单

| | main | rana-rp |
| --- | --- | --- |
| 定位 | 干活力：写代码、查资料、跑任务、微信应答 | 陪伴力：人格化对话 |
| 大脑 | 云端模型（dashscope provider） | 本地微调 `rana-rp-14b`（LM Studio） |
| 渠道 | 微信 + 网页 | 网页「Rana·RP」会话（可经快捷方式热切到微信） |
| 私密人格文件 | 不注入 | 经 persona-gate 钩子注入，**fail-closed**（钩子异常就拒绝服务，绝不裸奔） |
| 工具限制 | 可执行命令 | 禁 `ask_user`（微信渠道呈现不了交互提问卡，会卡死会话 15 分钟——血泪教训，已登记台账） |

多 agent 模式下网关要求请求显式指定 owner（`agentId`），这是前端所有请求都带 `agentId: "main"` 的原因。

### 记忆的三层结构

```
┌─ 各自 workspace 的记忆（MEMORY.md 即时注入 + 长期记忆库语义检索）
│
├─ 共享记忆桥产物（NTFS junction 双挂，双边可检索）
│    └─ 隐私规则：RP 侧原文永不出本机，过桥的只有本地提炼后的纪要
│       （另配一份不入 git 的隐私词表做本地兜底过滤，提示词层防护仍在）
│
└─ 私密记忆（独立目录：不在任何 workspace、不被记忆索引扫描、不被共享桥读取）
```

设计原则一句话：**数据往哪个层级流，取决于它最私密的时候在哪**。私密对话先在本地被提炼成「能见人」的纪要，才允许过桥；提炼这个过程本身也不经过任何云端。

### 公开镜像的隐私纪律

本仓库通过 `push-public.cmd`（`git add -A` 全量）镜像到公开仓库，所以**任何入库文件默认视为公开**：

- 密钥/token/个人账号 ID/私有仓库地址，绝对禁入；
- 状态目录（`.openclaw/`）、会话数据、SOUL/USER/MEMORY 等人格与记忆文件、日志、probe 调试脚本、隐私词表、私密记忆桥、Git 仓库清单（暴露本地目录结构）——全部在 `.gitignore` 里点名封禁；
- `push-public.cmd` 与 `backup-private.cmd` 本身也因含私有仓库地址而不入库。

## 🎮 深入：本地模型运维（12GB 显存生存指南）

在 4070 Ti 12GB 上让「一个 14B 模型常驻 + 随叫随到」稳定运行，是本项目踩坑最密集的区域，台账里有三篇大案。这里把结论沉淀成运维守则：

1. **LM Studio 的 JIT 按「模型 + 配置」区分实例**：同一个模型，两次以不同 `context_length` 加载 = 两份权重同时驻留显存。表现为模型名带 `:2` 后缀。解法：全卸载后，用与调用方**完全一致的参数**显式加载一份常驻（显式 load 无 TTL）。同参复打只会复用，不会再裂。
2. **查真实驻留要用 `/api/v0/models`**：`/v1/models` 会把没加载的也列出来，会骗人。
3. **parallel 槽会平分上下文**：`context_length=49152, parallel=2` = 每槽只有 24576。单请求预算（约 12.7k）+ 最大输出（8k）必须小于单槽，否则顶破。
4. **KV 缓存可以卸到系统内存**：48GB 内存充裕时，`offload_kv_cache_to_gpu=false` 让 GPU 只留权重，显存立刻宽松。
5. **压缩预算的硬地板**：OpenClaw 的上下文压缩预算公式里有一个 20000 token 的保留区下限——`contextWindow` 提到 24576 时预算仍是 8000，必须 ≥32768 预算才真正变大。预算太小会导致每 1~2 条消息就压缩一次，每压缩一次要动用两个模型（摘要 + 记忆冲刷），显存直接连环爆。
6. **memoryFlush 模型要跟着主模型走**：压缩时的记忆冲刷如果还指向换掉前的旧模型，那个旧模型会被反复拉进显存陪跑。脚本侧同理——记忆桥的提炼模型从 agent 配置动态读取，不写死。

## 🌟 技术亮点分析

以上是「怎么做的」，这一节回答「哪些做法值得你偷走」。

### 1. 「没有后端的全栈」：Vite 插件即后端
对一个纯本机自用工具，独立后端进程是纯负债：要管生命周期、要定接口协议、要处理跨进程配置。本项目把后端做成 Vite 插件挂进 dev/preview 两个服务器，**单进程、零部署、与前端同生命周期**；将来若真要上公网，这五个中间件可以原样搬进任何 Node HTTP 服务器，因为它们本来就只依赖 Node 标准 API，没有一行 Vite 私有代码。

### 2. 浏览器里的设备身份
不靠 cookie、不靠服务端会话表，用 WebCrypto Ed25519 完成「挑战-签名-验证」三步握手。这个模式值得一切「无后端/弱后端」的本地工具参考：**凭据（token）与身份（私钥）分离**，泄露前者不等于冒充。

### 3. 为不可靠世界设计的连接层
§8 那张防御工事表格的本质是一个认知：**本地进程≠可靠，SQLite 写入、渠道长连接、浏览器休眠都会制造竞态**。乐观创建的占位 key 协议（`pending-create:` 前缀 + Promise 队列 + 完成迁移）、删除的串行链 + 「超时先核实再重试」、消息三路到达的去重——每一招都对应一个真实踩过的坑（台账可查），不是教科书式防御。

### 4. 脏输出清洗管线
微调小模型的输出是「脏」的：伪思维链塞在 `<details>` 里、运行时注入的指令封套被原样吐回、甚至模仿着写出 `## Chat history` 的档案结构。`reasoning.ts` 用一条管线把这些全部洗干净：多源思考折叠（`<think>` / `<details>` 双语法、流式未闭合也要处理）→ 封套剥离 → 元块清除 → 回声检测（整条只剩封套时折叠成占位行）。**在 UI 层兜住模型层的问题**，是跟本地小模型共处的必修课。

### 5. 隐私是一等公民的架构，不是开关
隐私不是「加个加密」这种事后补丁，而是数据流本身的形状：私密对话的提炼发生在本地、过桥的只有纪要、私密记忆放在**结构上不可被索引**的目录、人格文件用 fail-closed 的钩子注入、公开镜像用 gitignore 点名封禁 + 全量提交前人工过闸。每一层的默认状态都是「不出去」。

### 6. 界面优先 + 文件契约的自动化
教训驱动的两条铁律：**自动化不许往聊天会话里塞消息**（早报曾占用车道，后来改成独立页面按需生成）；**功能必须长在界面上**（cron 系统任务关不掉？UI 如实标注而不是假装能关）。边车脚本与前端之间只用文件（`report.json`）对话，互相不依赖进程存活。按需生成 + 进程互斥锁把 API 额度从「每天固定烧」变成「用了才烧」。

### 7. 把踩坑制度化：人和 agent 共读的台账
`KNOWN-ISSUES.md` 不只是笔记，它是**写给下一个 code agent 的程序**：统一的「症状/根因/解决方案/状态」模板，AGENTS.md 规定排障先查它、解决后必须回写。同一个坑第二次出现时（如 LM Studio 双实例第二次发作），直接模式匹配到旧条目，几分钟收敛。配套的两层 AGENTS.md 体系（全局红线 + 项目规范）让任何一家 code agent 进场都自带同一套纪律。

### 8. 中文 Windows 环境的生存补丁集
GBK 输出解码、PowerShell 显式 UTF8、Node `--tls-max-v1.2` 绕 TLS 1.3 后量子 ClientHello 兼容问题、Hyper-V/winnat 动态端口保留段圈占代理端口（`net stop winnat` 大法）——这些平台怪癖每一个都能耗掉一晚上，本项目全部踩过、全部登记、全部有照方抓药的命令。

### 9. 定量化的模型运维
显存问题不靠玄学靠算术：压缩预算公式推导、parallel 槽平分上下文的验算、JIT 双实例的机理归因、KV 卸载的取舍——§12 的每条守则背后都有一次完整的测量与复验记录。这套方法比任何「调参秘籍」都可靠。

### 10. 角色浓度是工程出来的
「她的房间」不是贴图：墙、窗、搁板上的抹茶芭菲/毛线球/铃铛、角落的 ESP POTBELLY 吉他剪影，全是 CSS/SVG 手绘（不引版权图）；主题系统用 `color-mix` 从一个 accent 变量派生整套配色，用户粉气泡固定不随主题漂移；所有动画尊重系统「减少动态效果」设置。角色一致性靠设计系统，不靠贴皮。

## 🧯 排障与已知问题

**排障第一步永远是查 [KNOWN-ISSUES.md](KNOWN-ISSUES.md)**——先搜症状关键词，命中直接照方抓药。台账当前已登记的典型案件：

- 微信会话被 `ask_user` 卡死 15 分钟（已禁用该工具）+ 微信长连接假死（重启网关即愈）；
- 微信主动推送依赖 contextToken（上游限制：用户先发一条消息即恢复）；
- LM Studio 同模型双实例挤爆显存（§12 守则 1）；
- Clash 代理端口 7897 被 Hyper-V 动态端口保留段圈占 → git 推送挂死（`net stop winnat` 重算）；
- 大文件卷进 git → 推送永久挂死 → 心跳连环超时（reflog + gc 手术）；
- cron 会话删除报 `did not finish stopping`（placement 残留，需按 session_key 手术）；
- Windows 网关下 cron 命令要用 `--command-argv` JSON 数组（没有 sh 可用）。

**日常运维**：

- 重启网关：任务管理器结束 node 进程（或 `taskkill`）→ 重跑 `rana-web/start-gateway.cmd`（无服务注册，进程死了就是死了）；
- 网关日志：`rana-web/.gateway.log` 与 `%TEMP%\openclaw\openclaw-当日.log`（搜 `stalled session`、`timer tick failed` 等关键词）；
- 前端排障：浏览器控制台（连接层日志都带 `[gateway]` 前缀）+ `window.gw` 调试钩子可直接在控制台调用网关接口。

## ❓ FAQ（新手高频）

**Q：打开页面一直「未连接」？**
网关没起来。跑一遍 `start-rana.cmd`；还不行就看设置里 token 填了没（连接层报「缺少 gateway token」时会在横幅里明说）。

**Q：她在微信和网页上是同一个她吗？**
是。同一个网关、同一份会话存储，两个入口只是两扇窗。微信上聊到一半，回电脑前打开网页能接着上下文继续。

**Q：为什么她的回复里有一段灰色的「思考过程」？**
本地模型习惯把推理写在正文前。前端解析出来折叠了，点开可看，顶栏 💭 按钮可整体关闭。

**Q：某个定时任务想关但开关是灰的？**
那是 OpenClaw 内置的系统级任务，上游不开放单独启停（只能全局配置关）。UI 如实标了「⚙ 系统」。

**Q：显存又爆了/机器很卡？**
按 §12 守则逐条检查：`/api/v0/models` 看有没有 `:2` 实例、有没有旧模型陪跑、contextWindow 是否 ≥32768。

**Q：想自己改点什么，从哪下手？**
加页面：`src/components/` 建组件 → `App.tsx` 挂视图 → `TopNav.tsx` 加页签。要本地数据就照 `ranaSysStatusMiddleware` 的样子在 `vite.config.ts` 加一组中间件（记得回环校验）。改之前读一遍根目录 `AGENTS.md` 的规矩。

**Q：为什么叫 Rana？界面为什么长这样？**
原型是 MyGO!!!!! 的要乐奈：铃铛、异色瞳（导航栏那对双色圆点）、乐奈绿主色、墙上的吉他，都是给她的应援。设计稿的演进过程（五版）完整保留在 `rana-web/design-mockups/`。
