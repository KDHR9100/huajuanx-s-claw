# ADR-0002：OpenClaw 基底保留，不换自研运行时

- 状态：已采纳（2026-11-14，主人全权委托按推荐值采纳）
- 背景文档：HANDOFF-cli-bridge-20261114.md §2.2、KNOWN-ISSUES「draining/rollover 坏死病」条目

## 背景

11-14 架构体检（两侦察兵+登记库实查+补丁盘点）评估「基底要不要换」。现状：产品层（25 组中间件+13 边车+12 页签网页）100% 自研且运转良好；基底（npm openclaw 2026.9.7）质量不均——会话/工作池管理层 4 起大病（\?\路径秒拒、DataCloneError、Async work scope closed、draining/rollover 坏死病），靠 4+1 刀 dist 补丁压制。每次升级需重打全套补丁（锚点对不上需重新移植）。

## 决策

1. **保留 OpenClaw 基底，不换自研运行时**。理由：换基底=人月级重做渠道插件×2+cron+会话登记+agent 工具循环+记忆索引，且网页围着网关协议 v4 建，产品层适配也要重写；需求未质变前不值。
2. **持续收拢自研层**（体检卡 1-7 顺序推进）：产品层是基底无关的——文件契约、/__rana 端点、会话桥全是自研接缝；真到换基底那天，产品层全部保留，只换发动机。
3. **补丁刀数管理**：当前 5 刀（目录看门狗、创建路径、私密门、收图+指北、drain/rollover），重打脚本全部在 state `tmp/apply-*.cjs`，升级后全套重跑。
4. **重评触发线（命中任一条即重新评估换基底/fork）**：
   1. 补丁刀数 > 6 刀；
   2. 上游断供或方向背离（停更/隐私架构冲突）；
   3. 需求质变（公网部署/多用户/多机协同——"仅本机回环"形态不适应）；
   4. 升级回归成本失控（每次升级耗时 > 1 天）。
## 否决的替代方案

- **fork 深改**：4+1 刀补丁变正式分支代码，省锚点重打；换来永久 merge 负担与升级同步人肉成本，补丁管理已经是成熟制度，不值。
- **全自研基底**：完全可控，人月级重做；需求质变前不值（详见 §决策 1）。
- **立即升级 openclaw 到最新版**：9.8 未修创建路径病（见 KNOWN-ISSUES 网关卡死家族），升级=重打全套补丁+全量回归的成本，无对症新修复，不做。
- **立即换全自研+公网部署**：需求未质变，触发线未命中。

## 后果

- 正面：零迁移成本；病可控有先例（每起病都有台账+补丁刀先例）；收拢自研层同时积累适配层。
- 负面：会话管理层上游病要继续靠补丁刀压制，补丁税延续；锚点断则重新定位刀口（第 5 刀脚本已带明确报错退出，锚点变了会明说）。
- 中性：触发线命中时重评，届时产品层适配面=文件契约+会话桥+CLI 桥（本次收拢完成后，这层就是天然接缝）。
